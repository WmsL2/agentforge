# Configuration Reference

Authoritative model: `backend/app/core/config.py`. See [environment contract](../ENV_VARS.md)
for complete input/derived-field, precedence, credential, Provider and safe-diagnostic policy.

## Development and production sources

Development uses private `backend/.env`, prepared manually from `.env.example`.
Current-directory then parent-directory discovery remains convenient for local use.
Production uses private `backend/.env.prod`, prepared manually from the separate
public `.env.prod.example`; no real file or credentials are generated by code.

Use ENVIRONMENT=production for environment-only loading, or AGENTFORGE_ENV_FILE
with an explicit production file path. Production never discovers development .env.
The explicit file selector forces production mode and rejects a conflicting process
or constructor environment. AGENTFORGE_ENV_FILE=none disables file discovery.
Settings(_env_file=None, ...) explicitly isolates files while retaining process env.
Precedence: constructor > process > selected dotenv > defaults; production mode is
locked. Empty production values cannot fall through. Production dotenv values do
not expand variables; Compose credentials containing special characters must be
single-quoted. Give raw credentials to Settings, never pre-encoded values.

## Safe preflight

After selecting production mode/file in the process environment, from backend:

```bash
python -c "from app.core.config import settings; print('CONFIGURATION_VALID')"
```

Only success or bounded CONFIGURATION_INVALID/schema-field or
CONFIGURATION_SOURCE_INVALID diagnostics cross load_settings at bootstrap. It
catches malformed/nested source errors without printing their values or chains.
Do not dump Settings, credential URLs, raw Pydantic errors or Compose-rendered
secrets. Direct Settings construction is for programmatic consumers/tests, not
an operational diagnostic replacement. Validation does not connect to services.

### Customizing Available Models

Override `AI_AVAILABLE_MODELS` in `.env` to customize the model selector:

```bash
AI_AVAILABLE_MODELS=["gpt-5.5","gpt-5.4","claude-opus-4-7"]
```

## MCP stdio servers

`MCP_STDIO_SERVERS` configures application-managed MCP servers. Its default is
an empty JSON array (`[]`), so MCP is disabled until at least one server is
configured. The value must be a JSON array of objects with required
`namespace` and `command` fields, plus optional `args` and `env` fields.

```bash
MCP_STDIO_SERVERS=[{"namespace":"github","command":"npx","args":["-y","@example/github-mcp"],"env":{"GITHUB_TOKEN":"replace-with-your-local-secret"}}]
```

Each discovered remote tool is registered locally as
`namespace__remote_name`. For example, remote `create_issue` from the
`github` server becomes `github__create_issue` for the LLM; execution maps it
back to `create_issue` for the MCP client. v0.5 supports stdio only—HTTP/SSE,
OAuth, persisted connections, and frontend MCP management are not configured.

## Celery

| Variable | Default | Description |
|----------|---------|-------------|
| `CELERY_BROKER_URL` | derived REDIS_URL | Local/test override; production omitted or exactly canonical |
| `CELERY_RESULT_BACKEND` | derived REDIS_URL | Local/test override; production omitted or exactly canonical |
| `WORKFLOW_BACKGROUND_LEASE_SECONDS` | `900` | Workflow execution claim lease duration; must be greater than zero |
| `WORKFLOW_RECOVERY_SCAN_INTERVAL_SECONDS` | `60` | Celery Beat recovery scan cadence; must be greater than zero |
| `WORKFLOW_RECOVERY_BATCH_SIZE` | `100` | Maximum recoverable runs selected per scan; must be greater than zero |
| `WORKFLOW_RECOVERY_REDISPATCH_DELAY_SECONDS` | `60` | Minimum database-clock delay before the same recoverable run can be selected again; must be greater than zero |

Celery Beat, not each Celery worker, publishes the periodic recovery scan task.
The scanner only discovers and re-dispatches bounded PostgreSQL candidates; it
does not execute workflow nodes itself. Its durable last/next-dispatch schedule
prevents an earlier permanently recoverable row from starving later candidates.

## Production validation and deployment

Production requires explicit SECRET_KEY, API_KEY, POSTGRES_PASSWORD, REDIS_PASSWORD,
POSTGRES_HOST/PORT/USER/DB, REDIS_HOST/PORT/DB, FLOWER_USER/PASSWORD,
CORS_ORIGINS, DEBUG and DB_ECHO. Flags must be false; origins must be nonempty
and contain no wildcard. Secrets reject blanks, controls and known example/default
placeholders; SECRET_KEY retains its 32-character minimum. Valid secrets are not
trimmed. Flower user/password must not contain colon/comma; username also rejects
whitespace. Ports are bounded and REDIS_DB nonnegative. See ENV_VARS.md for exact policy.

Optional Provider keys may be empty when the capability is unused. Configured keys
are validated against blanks/placeholders, and corresponding model/provider inputs
must be nonblank. Endpoints are HTTP(S) with valid host/port and no embedded
credentials/query/fragment/whitespace; empty endpoints retain SDK defaults.
Production EMBEDDING_DIMENSIONS must be 1536. KNOWLEDGE_AGENT_ENABLED=true
requires both LLM and Embedding configuration, as does full-platform staging.
Legacy OPENAI_API_KEY cannot substitute for LLM_API_KEY. Configuration is not
connectivity; unavailable capabilities must not be reported as operational.

All production Make commands and backend role env_file inputs use backend/.env.prod.
Shared mappings propagate the same Compose-resolved connection credentials across
API, Worker, Beat, Flower and infrastructure despite shell/env_file precedence.
All roles enforce production and derive canonical Celery URLs; migration exec in
API inherits these settings. No production runtime verification is implied.

## Production Checklist

Before deploying to production, ensure these variables are properly set:

1. `SECRET_KEY` -- Generate a unique 64-character hex key: `openssl rand -hex 32`
2. `API_KEY` -- Generate a unique key: `openssl rand -hex 32`
3. `ENVIRONMENT` -- Set to `production`
4. `DEBUG` -- Set to `false`
5. `POSTGRES_PASSWORD` -- Use a strong, unique password
6. `CORS_ORIGINS` -- List only your actual frontend domain(s)
7. `REDIS_PASSWORD` -- Set a strong password
8. `LLM_API_KEY` -- Required when Platform Runtime capability is configured for use
9. `LLM_PROVIDER`, `LLM_BASE_URL`, `AI_MODEL`, and `AI_TEMPERATURE` -- Match the configured compatible provider
